## Highlights

CAIPE 1.3 brings hosted and native agentic applications into a more unified
experience. People can launch apps from a richer catalog, work with an
app-owned assistant in the same chat flow, organize chat history with folders,
and connect linked Webex conversations to app assistants. The release also
adds remote A2A agents, broader knowledge ingestion, and more flexible
authentication and authorization options.

<!-- truncate -->

## What's New

### Apps and chat

- **Unified app experience** — Hosted and native applications can share one app
  contract, catalog, navigation, and assistant experience. App-owned assistants
  can use their own conversations and streaming endpoints while keeping the
  surrounding chat selection intact ([#2852](https://github.com/caipe-io/ai-platform-engineering/pull/2852),
  [#2693](https://github.com/caipe-io/ai-platform-engineering/pull/2693)).
- **A more useful app catalog** — Search app metadata, browse refreshed catalog
  cards, and save personal favorites ([#2977](https://github.com/caipe-io/ai-platform-engineering/pull/2977),
  [#3109](https://github.com/caipe-io/ai-platform-engineering/pull/3109)).
- **Organized chat history** — Group chats by agent or personal folders, and
  create, rename, move, and remove folders ([#3019](https://github.com/caipe-io/ai-platform-engineering/pull/3019)).
- **Native app chat controls** — Native apps can use the host's conversation
  actions and feedback form, including an optional, editable chat excerpt that
  is excluded unless the reporter chooses to include it ([#3037](https://github.com/caipe-io/ai-platform-engineering/pull/3037),
  [#3038](https://github.com/caipe-io/ai-platform-engineering/pull/3038)).
- **Webex app assistants** — Linked-user Webex chats can reach compatible
  app-owned assistants ([#3070](https://github.com/caipe-io/ai-platform-engineering/pull/3070)).

### Agents and integrations

- **Remote A2A agents** — Administrators can register remote agents and make
  them callable tools, with configurable authentication and optional streaming
  ([#2373](https://github.com/caipe-io/ai-platform-engineering/pull/2373)).
- **Harness Engine foundation** — Add an opt-in portable runtime and gateway
  for application-specific harnesses; Dynamic Agents remains the default
  runtime ([#2401](https://github.com/caipe-io/ai-platform-engineering/pull/2401)).
- **More RAG sources** — Ingest a Confluence folder or whole space, and ingest
  web pages protected by header-based authentication ([#2805](https://github.com/caipe-io/ai-platform-engineering/pull/2805),
  [#2808](https://github.com/caipe-io/ai-platform-engineering/pull/2808)).
- **SharePoint documents** — Stream supported PDF and PowerPoint content and
  use document versions for incremental ingestion ([#2903](https://github.com/caipe-io/ai-platform-engineering/pull/2903),
  [#2911](https://github.com/caipe-io/ai-platform-engineering/pull/2911)).
- **Reasoning controls** — Configure reasoning effort for supported agents
  ([#2798](https://github.com/caipe-io/ai-platform-engineering/pull/2798)).

### Identity and administration

- **Authenticated local development** — Sign in with local Keycloak accounts;
  anonymous and synthetic administrator sessions are no longer used
  ([#2906](https://github.com/caipe-io/ai-platform-engineering/pull/2906)).
- **Identity and access visibility** — Admins can inspect identity links,
  membership sources, and access summaries for users ([#2810](https://github.com/caipe-io/ai-platform-engineering/pull/2810)).
- **Deployment-owned OpenFGA model** — Configure a complete authorization model
  through a ConfigMap while the chart continues to manage initialization
  ([#2940](https://github.com/caipe-io/ai-platform-engineering/pull/2940)).
- **Secondary OIDC authentication** — Applications can opt into a host-managed
  secondary identity trust and linking flow ([#3116](https://github.com/caipe-io/ai-platform-engineering/pull/3116)).

## Security

This release updates vulnerable dependencies and runtime components, including
patched Node and Python tooling, and fixes vulnerabilities in RSA verification,
glob processing, and documentation query parsing
([#2918](https://github.com/caipe-io/ai-platform-engineering/pull/2918),
[#2921](https://github.com/caipe-io/ai-platform-engineering/pull/2921),
[#3088](https://github.com/caipe-io/ai-platform-engineering/pull/3088),
[#3106](https://github.com/caipe-io/ai-platform-engineering/pull/3106)).
Webex meeting recording passwords and host keys are also redacted
([#2996](https://github.com/caipe-io/ai-platform-engineering/pull/2996)).

## Breaking Changes

- **Local development requires authentication.** Use a local Keycloak account
  when no upstream identity provider is configured. Anonymous login and
  synthetic administrator sessions are no longer supported.
- **Scheduled agent identity defaults changed.** The chart now uses a dedicated
  scheduler-runner client and requests task-owner identity. External identity
  providers must support RFC 8693 token exchange for this flow. Review the
  upgrade guide before upgrading deployments that override scheduler
  authentication or use an external identity provider.

## Known Issues

None known at the time of this draft.

## Upgrade Guide: 1.2.0 → 1.3.0

### Overview

The chart values are additive: no existing values keys are removed or renamed.
Review the scheduler identity default change, especially when using an external
identity provider or overriding scheduler authentication. This guide compares
chart 1.2.0 with the latest available 1.3.0 release candidate (1.3.0-rc.26);
repeat the chart diff against the final 1.3.0 chart before applying the upgrade.

### Helm Values Changes

#### Breaking Changes

No chart values keys are removed, renamed, or type-changed. However, the default
`autonomous-agents.dynamicAgentsAuth` client settings changed. With the bundled
Keycloak configuration, the chart supplies the scheduler-runner client. External
identity providers must support RFC 8693 requested-subject token exchange to
run scheduled work as its owner.

If your deployment overrides this block, compare it with the new defaults and
configure the scheduler-runner client secret. Do not keep the previous
platform-client credentials unless your deployment intentionally uses a
custom compatible token-exchange setup.

#### New Optional Fields

| Key | Default | Description |
|---|---|---|
| `caipeDatabase.manageExternalSecret` | `false` | Let the chart manage the shared UI database ExternalSecret. |
| `caipeDatabase.backend` | `mongodb` | Select MongoDB or AWS DocumentDB for the shared database URI. |
| `caipeDatabase.secretName` | `""` | Target Secret name; should match `caipe-ui.existingSecret`. |
| `caipeDatabase.documentdb.remoteKey` | `""` | Secret-store key containing the DocumentDB URI. |
| `caipeDatabase.documentdb.host` | `""` | DocumentDB hostname used by UI health checks. |
| `openfga.init.existingModelConfigMap` | `""` | Use an existing ConfigMap with a complete authorization model; empty uses the bundled model. |
| `autonomous-agents.enabledWebhookProviders` | `[github, jira, slack, pagerduty]` | Restrict which supported providers can be configured for webhooks. |
| `autonomous-agents.dynamicAgentsAuth.audience` | `caipe-platform` | Audience requested for the scheduler identity token. |

The chart also adds the optional `mcp-sharepoint` configuration, disabled by
default, for deployments that use the SharePoint MCP server.

#### Default Changes

| Key | 1.2.0 | 1.3.0-rc.26 | Impact |
|---|---|---|---|
| `autonomous-agents.dynamicAgentsAuth.clientId` | `caipe-platform` | `caipe-scheduler-runner` | Scheduled calls use the dedicated scheduler-runner client. |
| `autonomous-agents.dynamicAgentsAuth.scope` | `openid profile email` | `""` | The scheduler flow uses the audience and owner token exchange settings. |
| `autonomous-agents.dynamicAgentsAuth.clientSecretRef.name` | `caipe-platform-secret` | `""` | The default Secret name is no longer preselected. |
| `autonomous-agents.dynamicAgentsAuth.clientSecretRef.key` | `OIDC_CLIENT_SECRET` | `KC_SCHEDULER_CLIENT_SECRET` | The bundled Keycloak Secret uses its scheduler client secret key. |
| `keycloak.image.tag` | `26.3` | `26.8.1` | The bundled Keycloak image is updated. |

#### Deprecated / Removed Keys

None.

### Upgrade Runbook

#### 1. Review scheduler authentication

Check whether your values file overrides `autonomous-agents.dynamicAgentsAuth`.
For the bundled Keycloak, use the chart's new scheduler-runner defaults. For an
external identity provider, verify RFC 8693 requested-subject token exchange
support and configure the appropriate client secret reference and token URL.

#### 2. Review optional integrations

If enabling the SharePoint MCP server, configure its required Secret. If using
an external OpenFGA model, provide a same-namespace ConfigMap containing the
complete composed `authorization-model.json`. These options are not required
for a standard upgrade.

#### 3. Update the chart

After the final 1.3.0 chart is published, update the chart version:

```bash
helm upgrade ai-platform-engineering \
  oci://ghcr.io/caipe-io/charts/ai-platform-engineering \
  --version 1.3.0 \
  -f your-values.yaml
```

#### 4. Verify

```bash
kubectl get pods -n <namespace>
kubectl get events -n <namespace> --sort-by=.lastTimestamp
```

Then verify sign-in, chat streaming, scheduled runs, and any enabled app,
SharePoint, or RAG workflows. Confirm the scheduler can obtain its configured
identity token.

### Personal Impact Analysis

No deployment `values.yaml` was supplied. For default Helm values, there are no
removed or renamed keys. Review the scheduler identity settings if you use an
external identity provider or have customized `dynamicAgentsAuth`.
