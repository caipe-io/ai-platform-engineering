## Highlights

CAIPE 1.3.3 adds optional JSON Schema based responses for agents, improves AWS
workload identity support in the AWS MCP server and RAG ingestor, and lets
administrators enable privacy-minimized application usage counts. The release
also improves Webex meeting transcript and calendar searches, app integrations,
and UI theme behavior.

<!-- truncate -->

## What's New

### Agent responses and integrations

- **Structured agent responses** — Apps can request optional JSON responses
  that follow an allowed schema, with results available through invocation and
  streaming responses ([#2715](https://github.com/caipe-io/ai-platform-engineering/pull/2715)).
- **AWS workload identity** — AWS MCP servers and the RAG ingestor can use
  container credentials or IRSA when assuming cross-account roles, reducing
  reliance on static credentials ([#2611](https://github.com/caipe-io/ai-platform-engineering/pull/2611),
  [#2975](https://github.com/caipe-io/ai-platform-engineering/pull/2975)).
- **Application usage insights** — Administrators can optionally view daily
  aggregate app-shell load counts, retained for 30 days and collected without
  user or session identifiers ([#3003](https://github.com/caipe-io/ai-platform-engineering/pull/3003)).
- **Custom identity profile attributes** — Secondary authentication profiles
  can reconcile configured user attributes while preserving protected identity
  permissions ([#3149](https://github.com/caipe-io/ai-platform-engineering/pull/3149)).

### Bug Fixes

- **Embedded apps**: apps can identify the running CAIPE host build without
  rebuilding the app when the host changes
  ([#3133](https://github.com/caipe-io/ai-platform-engineering/pull/3133)).
- **Webex meetings**: improve transcript recovery when recording occurrences
  are available and preserve requested calendar date windows
  ([#2997](https://github.com/caipe-io/ai-platform-engineering/pull/2997),
  [#2969](https://github.com/caipe-io/ai-platform-engineering/pull/2969)).
- **Streaming**: ignore heartbeat and metadata-only frames so they no longer
  appear as empty application events
  ([#3148](https://github.com/caipe-io/ai-platform-engineering/pull/3148)).
- **Dark themes**: restore dark styling for content inside themed areas
  ([#2999](https://github.com/caipe-io/ai-platform-engineering/pull/2999)).

## Upgrade Guide: 1.3.2 → 1.3.3

### Overview

This is a drop-in upgrade. The chart's values are unchanged between 1.3.2 and
1.3.3; no `values.yaml` edits are required. New capabilities such as aggregate
app usage counts and structured responses remain opt-in.

### Helm Values Changes

No Helm values changes between 1.3.2 and 1.3.3. The parent chart metadata and
dependency versions advance to 1.3.3; the parent chart values are identical.

### Upgrade Runbook

#### 1. Update the chart version

```bash
helm upgrade ai-platform-engineering \
  oci://ghcr.io/caipe-io/charts/ai-platform-engineering \
  --version 1.3.3 \
  -f your-values.yaml
```

#### 2. Keep your existing values

No values changes are required. To use optional features, follow their
component documentation for configuration:

- Application usage counts are disabled by default. The UI component README
  describes the opt-in setting and 30-day retention behavior.
- Structured responses are disabled by default. The Dynamic Agents README
  describes the capability and schema configuration.
- AWS workload identity requires suitable workload credentials and target-role
  trust. The AWS MCP and AWS ingestor documentation describes supported
  credential selection; this release does not create or change IAM policies.

#### 3. Verify

```bash
kubectl get pods -n <namespace>
kubectl get events -n <namespace> --sort-by=.lastTimestamp
```

Then verify sign-in, chat streaming, and any enabled AWS, Webex Meetings, or
embedded app workflows.

### Personal Impact Analysis

No deployment `values.yaml` was supplied. Since the chart values are unchanged,
existing values files need no migration. Review the component documentation
only if you plan to enable the opt-in features or use AWS workload identity.
