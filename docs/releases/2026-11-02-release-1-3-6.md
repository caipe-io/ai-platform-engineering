## Highlights

CAIPE 1.3.6 fixes how administrators target curated release notes to a host
release. The editor now shows the current host version, makes it easier to
retarget saved notes, and explains when notes are set for a different release
and will not appear on the current host.

<!-- truncate -->

## What's New

### Curated release notes

- **Clearer release targeting** — Administrators can see the current host
  release, use it as the target for new notes, and retarget existing notes
  without losing their content. The editor explains when notes are saved for a
  different release and will not appear on the current host
  ([#3204](https://github.com/caipe-io/ai-platform-engineering/pull/3204)).

## Bug Fixes

- **Release announcements**: fix curated notes being silently skipped when
  they were saved for an application's version instead of the deployed CAIPE
  host version ([#3204](https://github.com/caipe-io/ai-platform-engineering/pull/3204)).

## Breaking Changes

No breaking changes. Drop-in upgrade from 1.3.5.

## Known Issues

None known at the time of this release.

## Upgrade Guide: 1.3.5 → 1.3.6

### Overview

This is a drop-in upgrade. The chart values are unchanged between 1.3.5 and
1.3.6; no `values.yaml` edits are required.

### Helm Values Changes

No Helm values changes between 1.3.5 and 1.3.6. Existing values files can be
used as-is.

### Upgrade Runbook

#### 1. Update the chart version

```bash
helm upgrade ai-platform-engineering \
  oci://ghcr.io/caipe-io/charts/ai-platform-engineering \
  --version 1.3.6 \
  -f your-values.yaml
```

#### 2. Keep your existing values

No values changes are required.

#### 3. Verify

```bash
kubectl get pods -n <namespace>
kubectl get events -n <namespace> --sort-by=.lastTimestamp
```

Then open the curated release notes editor and confirm that it shows the
current host release. If notes target another release, the editor explains
that they will not appear on this host and offers **Use current host release**.

### Personal Impact Analysis

No deployment `values.yaml` was supplied. Since chart values are unchanged,
existing values files need no migration.
