## Highlights

CAIPE 1.3.4 helps users get started with app assistants through connection
instructions published by their administrators. Administrators can also tailor
release announcements by writing notes or selecting a Markdown file for a
specific release.

<!-- truncate -->

## What's New

### Assistant connection guides

- **Instructions where you need them** — Open an app's connection instructions
  from its assistant header; the panel stays open until you close it
  ([#3144](https://github.com/caipe-io/ai-platform-engineering/pull/3144)).
- **Guides for your channels** — Administrators can publish up to five guides
  per app, with Markdown instructions, optional action links, and an optional
  Webex logo
  ([#3144](https://github.com/caipe-io/ai-platform-engineering/pull/3144)).
- **Clearer assistant navigation** — Chat and History have their own row, and
  conversation actions appear on hover or keyboard focus, with controls
  available directly on touch devices
  ([#3144](https://github.com/caipe-io/ai-platform-engineering/pull/3144)).

### Curated release announcements

- **Choose what users see** — Administrators can enter release notes or select
  a Markdown file from an approved repository for a deployed release
  ([#3143](https://github.com/caipe-io/ai-platform-engineering/pull/3143)).
- **Preview and publish** — Preview entered notes before saving, check the
  published source afterward, and return to automatic notes when an override
  is no longer needed
  ([#3143](https://github.com/caipe-io/ai-platform-engineering/pull/3143)).
- **Updated notes remain discoverable** — Publishing changed curated content
  allows users to see the new announcement even if they dismissed its earlier
  revision
  ([#3143](https://github.com/caipe-io/ai-platform-engineering/pull/3143)).

## Bug Fixes

- **Archived chats**: countdowns and automatic removal now use the same
  seven-day period across time zones and daylight-saving changes
  ([#3144](https://github.com/caipe-io/ai-platform-engineering/pull/3144)).
- **AWS integrations**: release images include the command-line tools required
  by AWS and Kubernetes operations, with checks that the tools can run
  ([#3154](https://github.com/caipe-io/ai-platform-engineering/pull/3154)).

## Breaking Changes

No breaking changes. The new guides and curated announcements are optional.

## Known Issues

Automatic patch-release blog selection can fall back to changelog entries
instead of displaying the intended blog. The follow-up fix is tracked in
[#3155](https://github.com/caipe-io/ai-platform-engineering/pull/3155).
Administrators can select the intended file through the curated repository
override in this release.

## Upgrade Guide: 1.3.3 → 1.3.4

### Overview

The changes since 1.3.3 require no Helm values migration. Connection guides and
curated announcements are configured through the administration UI after the
upgrade. Existing deployments continue to use automatic release notes unless
an administrator selects an override.

### Helm Values Changes

The parent chart and subchart values are unchanged in the source changes for
this release. Existing `values.yaml` files can be retained.

Repository-based announcements use the existing
`caipe-ui.config.RELEASE_NOTES_ALLOWED_REPOSITORIES` setting. Its default permits
the upstream repository. An explicit list replaces that default; approve any
additional repository before selecting it in the UI. See the
[release-announcement configuration](https://github.com/caipe-io/ai-platform-engineering/blob/main/ui/src/components/settings/sections/README.md).

### Upgrade Runbook

#### 1. Update the chart version

After the 1.3.4 chart and images are published, upgrade using your existing
values:

```bash
helm upgrade ai-platform-engineering \
  oci://ghcr.io/caipe-io/charts/ai-platform-engineering \
  --version 1.3.4 \
  -f your-values.yaml
```

#### 2. Configure optional features

- **Connection guides:** open Admin → Platform configuration → Defaults →
  Assistant connection guidance. Choose an app, add instructions, preview, and
  save. Guides provide instructions; they do not link identities or grant
  access. A local Webex identity-link action appears only when identity linking
  is configured. See the
  [connection-guidance documentation](https://github.com/caipe-io/ai-platform-engineering/blob/main/ui/src/lib/agentic-apps/README.md).
- **Curated announcements:** open Admin → Platform configuration → Announcements
  → Curated release notes. Set the exact deployed release version, then choose
  entered Markdown or an approved repository file. Pin a tag or commit for
  reproducible repository content. Both sources are limited to 128 KiB of
  UTF-8 content; mutable repository refs are cached for ten minutes. Choose
  Automatic to restore the existing announcement behavior.
- **AWS tooling:** deploy the newly built AWS MCP image to receive the restored
  tools. Existing containers retain their installed tool versions until
  replaced. See the
  [AWS MCP documentation](https://github.com/caipe-io/ai-platform-engineering/blob/main/ai_platform_engineering/mcp/aws/README.md).

#### 3. Verify

```bash
kubectl get pods -n <namespace>
kubectl get events -n <namespace> --sort-by=.lastTimestamp
```

Verify sign-in and chat streaming. For configured apps, open a connection guide,
check keyboard focus and dismissal, and switch between Chat and History. For
curated announcements, use the current-release preview to check the saved
content and confirm it targets the deployed version. Verify enabled AWS
workflows after replacing the AWS MCP image.
