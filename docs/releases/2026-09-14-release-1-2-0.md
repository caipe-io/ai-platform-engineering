## Highlights

CAIPE 1.2 upgrades the platform to Python 3.14 and Node.js 24, refreshes the
JavaScript dependency stack, and improves streaming and audit reliability. The Helm
chart also adds safer workload defaults and a stable-key format for custom resources.

<!-- truncate -->

## What's New

- **Python 3.14** — All Python projects, images, CI jobs, and development workflows now
  use Python 3.14, with refreshed dependencies and compatibility updates
  ([#2722](https://github.com/caipe-io/ai-platform-engineering/pull/2722)).
- **Node.js 24 and js-yaml 5** — The UI, docs, repository tooling, and RBAC browser tests
  now use Node.js 24. Direct JavaScript consumers use js-yaml 5.4.1
  ([#2723](https://github.com/caipe-io/ai-platform-engineering/pull/2723)).
- **Consolidated administration** — Security & Policy now groups RBAC, chat, and
  self-check records under Audit, and access tools under Access Operations. Developer
  tools now live under Account & Access
  ([#2721](https://github.com/caipe-io/ai-platform-engineering/pull/2721)).
- **Slack bot maintenance** — Slack authorization, routing, conversations, actions, and
  streaming handling are split into focused modules with expanded regression coverage;
  user-visible behavior is unchanged
  ([#2596](https://github.com/caipe-io/ai-platform-engineering/pull/2596)).

## Bug Fixes

- Dynamic-agent timelines no longer trigger recursive React updates during high-volume
  streams ([#2719](https://github.com/caipe-io/ai-platform-engineering/pull/2719)).
- No-op policy reconciliations no longer create audit noise. Mutation and failure
  records now show the reconciliation scope and relationship counts
  ([#2720](https://github.com/caipe-io/ai-platform-engineering/pull/2720)).
- Development UI services receive consistent release metadata for System Health
  ([#2719](https://github.com/caipe-io/ai-platform-engineering/pull/2719)).
- Slack startup failures continue to stop the service cleanly after the internal
  reorganization
  ([#2596](https://github.com/caipe-io/ai-platform-engineering/pull/2596)).

## Security

- Workloads now default to non-root, least-privilege security contexts where supported.
- Service-account token automount is disabled where Kubernetes API access is not
  required.
- MCP servers, OpenFGA hooks, Keycloak jobs, and Milvus components now have default CPU
  and memory bounds.

See [#2469](https://github.com/caipe-io/ai-platform-engineering/pull/2469) for the full
Helm hardening changes.

## Breaking Changes

- `extraDeploy` is replaced by `extraDeployMap` with no compatibility shim.
- Python source builds and custom extensions require Python `>=3.14,<3.15`.
- UI, docs, repository tooling, and RBAC browser tests require Node.js
  `>=24.11.0 <25`.
- Retired Security & Policy and Developer URLs no longer redirect.

## Known Issues

- The test-only `@istanbuljs/load-nyc-config` dependency retains a transitive js-yaml
  4.3.1 compatibility override. Direct consumers use js-yaml 5.4.1.
- The RAG server remains on pymilvus 2.6.9 for compatibility with langchain-milvus
  0.3.3.

## Upgrade Guide: 1.1.0 → 1.2.0

### 1. Migrate custom Helm resources

Rename `extraDeploy` to `extraDeployMap` and give each resource a stable key.

```yaml
# Before
extraDeploy:
  - apiVersion: v1
    kind: ConfigMap
    metadata:
      name: example-config

# After
extraDeployMap:
  example-config:
    apiVersion: v1
    kind: ConfigMap
    metadata:
      name: example-config
```

Update Helm flags from `extraDeploy.<key>` to `extraDeployMap.<key>`. Resources left
under `extraDeploy` are not rendered.

If another deployment owns the Milvus service account, set:

```yaml
rag-stack:
  milvus:
    serviceAccount:
      ragStackManaged: false
```

### 2. Update build runtimes

- Use Python `>=3.14,<3.15` and recreate Python environments.
- Use Node.js `>=24.11.0 <25` and run clean dependency installs.

### 3. Update saved administration links

- RBAC Audit, Chat Audit, and Self Check move to `/admin/security/audit`.
- Access Explorer, Keycloak, and Migrations move to
  `/admin/security/access-operations`.
- Developer settings move to `/settings/account-and-access`.

### 4. Upgrade the chart

```bash
helm upgrade ai-platform-engineering \
  oci://ghcr.io/caipe-io/charts/ai-platform-engineering \
  --version 1.2.0 \
  -f your-values.yaml
```
